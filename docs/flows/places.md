# Places, species lists, maps, field guides and the compare tools

Read from the code on master at commit e81a8945 (2026-10-22). Paths are relative to the repo root; Java classes are under `src/org/calacademy/antweb/`. Traffic: production Tomcat log, 2026-10-11 to 2026-10-18 (8 days).

## In plain words

- **Maps** (`bigMap.do`, 139,996 requests in 8 days, second only to taxon overviews): the large map of a taxon's specimens in a place, of one specimen, a locality, a collection, a country or adm1, or a museum's specimens. Points open popups linking the localities and specimens.
- **Place pages** (country 2,129; adm1 1,514; museum 215; project 179; bioregion 145; region 11; subregion 5; island): the place's text (written by curators), its statistics table (subfamilies, genera, species, valid species, endemic, introduced, specimens, imaged specimens, images and views, each with its definition; see #191/#192; Subfamilies count valid subfamilies only on every kind of place, curated projects too, since 2026-10-30 (B67 of 2026-10-27 superseded); Endemic and Introduced, and their lists `endemic.do` and `introduced.do`, count flagged names with a counted status, never a synonym, B70, both since 2026-10-27, the stored numbers from the next nightly run), pie charts, a map of its specimens, and links to its **species lists**. List pages (`countries.do`, `regions.do`, `subregions.do`, `adm1s.do`, `bioregions.do`, `museums.do`, `projects.do`) list every place with its counts. The header Places box opens a place's page ([search.md](search.md)).
- **Species lists** (`taxonomicPage.do`, 2,443): the subfamilies, genera or species of a place, one row per taxon with status, author, specimen and image counts and a map flag, optionally with images (`images=true`), in one of four views (Valid, Curated, All specimen names, Fossil; below). The old `specimen=true` ("Show Specimen Taxa", later "Names from: Specimens collected here") opens All specimen names; nothing is kept in the session. Country and adm1 lists take valid names from specimens; since 2026-10-29 they also have the genus (with its subfamily) of every specimen identified to genus, such as "Lividopone (indet)" in Mozambique, without the name itself (nightly set 2; [nightly.md](nightly.md), numbers.md row 21). Bioregion and museum lists already had them.
- **Where the names come from: the four views** (Brian Fisher, 2026-11-02; replaces the status menu and the "Names from" selector of 2026-10-30). The list header is two lines: the header (its number always the rows of the chosen view: "2,700 Species (valid and curated)") with four buttons on the right, a segmented control: **Valid | Curated | All specimen names | Fossil**, the same on every kind of list (countries, adm1s, regions, subregions, bioregions, museums, projects, All AntWeb); under it small links, "List all specimens collected in <place>" and "Edit Species List" (any curator or administrator, below). **Valid**: names AntCat calls valid, from specimens (not red-flagged), curated entries or literature. **Curated** (the default everywhere): Valid plus the curated morphospecies: a morphospecies is curated once a curator has put it on any species list (a curator's `geolocale_taxon` or `proj_taxon` entry, `ListView.vettedCondition`, computed when the page is shown); it then shows on every place where it is on the list or, on countries, adm1s, regions and subregions, where its specimens were collected, unless a curator removed it from that place's list (a dispute: that place only). **All specimen names**: Curated plus every other morphospecies and every name identified only to genus ("Acropyga (indet)"); a genus known in the place only from such specimens is listed only here. **Fossil**: fossil names. Red-flagged specimens never count, in any view. Country and adm1 lists take valid names, not morphospecies, from specimens, so on geolocales Curated and All specimen names add the names of specimens collected there (`TaxaPage.specimenNamesWhere`; such a row is marked with the yellow ant and shows its specimens here); bioregion, museum and All AntWeb lists already take every specimen name. **Rows, one line each**: Taxon name | Author date | Species (genus rows: the species of the genus in the view, or "&ndash;"; subfamily rows, since 2026-11-03 (B77): Genera, the genus rows the subfamily's browse page shows in the same view, linked to it, `ListView.SubfamilyRows`, a few queries per page) | **Not curated** (genus rows, views Valid and Curated, on countries, adm1s, museums and bioregions: the specimens of the genus collected here, not red-flagged, whose name is not curated: uncurated morphospecies, names identified only to genus, names not in AntCat; counted once a day, nightly set 4 and `utilData.do?action=placeGenusCuration`, `PlaceGenusCurationDb`; hover "N specimens not curated"; linked to the genus page in the place in the view Not curated, whose header gives the breakdown; empty when 0; it replaced Other specimens, read live on every page, on 2026-11-02) | Images (genus rows: "N species imaged", the species of the view with an image of the ant) | Map | **Source**, an icon: specimen, curated, literature (Bolton's catalogue) or AntCat (rows from the AntCat import, hover "From the AntCat import"), with the word as title; a name with a specimen collected here shows specimen even when it is also in the literature. Acropyga in Mozambique (morphospecies collected there) is in Valid with "&ndash;" and its Not curated number. A few queries per page, none per row (`ListView.GenusRows`), on genus lists and a subfamily's browse page in a place; genus lists read the names collected in the place from `place_specimen_name` (stored with the Not curated numbers), not the specimen table. The genus page in a place, in Valid and Curated, says above the notes on specimen and image counts "Specimens collected here not on the species list: 3 (names: Acropyga mz01, Acropyga mz02)" (the indet name is one of them; in All specimen names those names are on the list; in all of AntWeb the indet line is unchanged). "About this list" (a closed `<details>`) explains the views, the columns and the icons in plain words, then the list's sources. The Fossil button shows only when the list has fossil names in the place (`ListView.hasFossil`). Curated was first called Vetted: `statusSet=vetted` still opens it. **Editing**: any curator may edit any place's or project's species list (Brian Fisher, 2026-11-02, to encourage participation; `SpeciesListAccess.canEdit`; the AntCat and All AntWeb lists stay with administrators); every change is recorded with the curator (`geolocale_taxon_log`, `proj_taxon_log`, disputes with `curator_id`). Editing a project's page and settings stays with the curators it is assigned to. **Removed names** (Brian Fisher, 2026-11-03: transparency, "if something is deleted, we still need transparency"): the view All specimen names shows a name removed from the place's list when specimens of it were collected there (Curated and Not curated leave it out), marked after its name in red, on one line: "removed from the list by <curator or job> (<date>): <reason>" (the reason cut to 80 characters, the whole text as the hover title, all escaped; `ListView.loadRemovals`, `removedMarkHtml`: the disputes and the newest `list_removal_log` row of each name not on the list now, one load per page). A curator who removes names with the Species List Tool can give a reason ("Reason for removing (shown with the name)", one line, optional) kept on the dispute and in `list_removal_log`; the nightly clean-up (morphospecies with no specimens, names no longer in AntWeb) and the orphan tool record their removals there too (docs/data-model.md, `list_removal_log`).
- **Field guides** (`fieldGuide.do`, 286; needs a login): a printable page with an image, a map and the habitat summaries of each taxon, either of a taxon's children in a place ("Create Field Guide" on a genus or subfamily page) or of a whole rank in a place (the Field Guides menu of a place's species list: Subfamilies / Genera / Species of <place>). From search results: `fieldGuideResults.do`.
- **Compare tools** (need a login): **Compare Images** (`getComparison.do`, 16,740) shows the head, profile and dorsal images of a taxon's children side by side; **Map** of the children (`mapComparison.do`, 7,023) one small map per child taxon. Anonymous visitors get a message asking them to log in.

Nothing is cached per request: species lists, maps and field guides are built from the database each time. Place maps (country, adm1, museum) are read pre-computed from `object_map` (nightly set 5); taxon, specimen, locality and collection maps are computed live. The site allows **3 maps, 2 image comparisons, 2 map comparisons and 3 field guides at the same time** for all visitors together (static counters); above that the visitor gets "Simultaneous ... limit exceeded. Please try again later" (finding F2).

## Code path

- **Place pages:** `OverviewAction.execute()` (one class for all place and list pages; form `OverviewForm`): `GeolocaleMgr` / `ProjectMgr` / `MuseumMgr` / `BioregionMgr` (in memory) find the place; `action=recalc` (curators, POST) recounts it (`GeolocaleDb.updateCounts`, `ProjTaxonCountDb`, `MuseumDb.populate`, `BioregionDb.populate`, `PlaceImageCountDb.updatePlace`); `saveDescriptionEdit()` / `prepareDescriptionEdit()` (page text); `ObjectMapDb.getGeolocaleMap()` / `getMuseumMap()` (the map); `setPlaceImages()` (`PlaceImageCountDb.read`, the image numbers). JSPs `country.jsp`, `adm1.jsp`, `region.jsp`, `subregion.jsp`, `bioregion.jsp`, `museum.jsp`, `project.jsp` share `overview-body.jsp` (statistics table `id="place-stats"`, species list links); the lists share `overviews-body.jsp`. `geolocale.do` redirects; `place.do` is `geolocale.PlaceNameAction` (search.md).
- **Species lists:** `TaxaPageAction.execute()`: the place (`OverviewMgr`), `Rank.isValid(rank)`, `StatusSet.getStatusSet()` (the view of 2026-11-02: valid, curated, all, fossil, from the address, else Curated, never the session; `specimen=true` without a view gives all; `StatusSet.listStatusSet` gives its criteria; buttons `common/statusesDisplay.jsp`, header `StatusSet.listHeading`, docs/numbers.md "Views of lists"), `TaxaPage.fetchChildren(...)` (the place's list joined to `taxon`, and on geolocales in Curated and All specimen names the names of specimens collected there, `TaxaPage.viewQuery`); subspecies refused. JSP `taxonomicPage.jsp` + `taxonomicPage-body.jsp` (`common/overviewHeading.jsp` with the Field Guides menu, the header with `common/statusesDisplay.jsp`, `common/taxonSetHeaderNotes.jsp` "About this list"; `taxonReportBody.jsp` rows) or `taxonomicPageImages-body.jsp`. Genus lists: `TaxaPage.findGenusRows` (`ListView.loadGenusRows`: the genus rows' Species, Not curated and species imaged in the view and the rows the view shows); species lists: `TaxaPage.findPlaceSpecimens` (source icons, rows added from specimens); a subfamily's browse page in a place: `BrowseAction` (request attribute `placeGenusRows`, read by `taxonReport.jsp`).
- **Field guides:** `search.FieldGuideAction.execute()`: `Check.loginForFeature()` (anonymous: the explained log-in page, then back); the place; a taxon (`TaxonDb.getFullTaxon` -> `setChildren` / `setChildrenLocalized`) or a rank of the place (`TaxaPage.fetchChildren`); `FieldGuide.setMembers()` (images, maps, habitat summaries of each taxon). JSP `search/fieldGuide.jsp` + `fieldGuide-body.jsp`. From search results: `FieldGuideResultsAction`.
- **Compare tools:** `BrowseAction` with `cacheType` getComparison or mapComparison ([taxon-pages.md](taxon-pages.md)): login required (anonymous visitors get the explained log-in page with return, `Check.loginForFeature()`, since 2026-10-26, F15; before, `Login.MUST_LOGIN_MESSAGE`), the simultaneous limit, `setChildren(..., getChildImages, getChildMaps ...)`; mapComparison builds one `Map` per child. JSPs `comparison.jsp` + `comparison-body.jsp`, `mapComparison.jsp` + `mapComparison-body.jsp`. The form is session scope (`browseForm`).
- **Maps:** `BigMapAction.execute()`: the place (`OverviewMgr`); `getMap()`: a taxon (`TaxonDb.getTaxon` -> `MapMgr.getMap(taxon, place)` or `new Map(taxon, place, connection, geolocaleFocus)`), a locality (`LocalityDb`), a collection (`CollectionDb`), a specimen (`SpecimenDb.exists`, `new Map(list)`), a geolocale or museum (`ObjectMapDb`); "No map found for target:..." otherwise. JSP `dynamicMap.jsp` + `dynamicMap-body.jsp` + `maps/googleMapInclude.jsp` (Leaflet; the popups are tested by test_site_links.py and tests/unit/test_map_popups.py). Bots get "Log In to see maps." instead of the map.

- **Which specimens are a place's** (the same rule for every number, list, view and download of the place): a country
  `specimen.country` = its name (the views and specimen names also `island_country`, each specimen once), an island
  `specimen.island_country`, an adm1 `specimen.country` = its parent country and `specimen.adm1` = its name (B26, fixed
  2026-11-09, Brian Fisher: `Geolocale.adm1Criteria`; a state of the same name in another country, or a specimen with
  that adm1 and no country, is not its; before, the name alone), a museum `specimen.museum`, a bioregion
  `specimen.bioregion`, a region or subregion the specimens of its countries. Each condition can use an index of the
  specimen table (docs/data-model.md, `specimen`, "Indexes and the place queries").
- **Red flags (decision of 2026-10-30: one rule for every list):** a list row made from specimens never comes from a red-flagged specimen ("loaded, hidden from most pages until fixed"), on every kind of place: country and adm1 lists (`GeolocaleTaxonDb.insertGeolocaleTaxaFromSpecimens`, also the genus rows of specimens identified to genus), bioregion lists (`BioregionTaxonDb.speciesFromSpecimenSql`, set 3) and museum lists (`MuseumDb.speciesFromSpecimenSql`), one condition `SpecimenDb.notRedFlagged`. docs/numbers.md "Red flags: one rule for every list".

## Old names in links

AntWeb keeps an old name of a place as a not-valid place whose valid name is the current one (USA: United States; MA: Massachusetts; after a country's rename, Ivory Coast: Côte d'Ivoire; docs/runbook.md, "Renaming a country"). Since 2026-11-10 a page request (GET) that names a country or an adm1 by such an old name is answered with a permanent redirect (301) to the same address with the current name, URL-encoded, every other parameter as it was (`util/OldPlaceNames`, called by `SessionRequestFilter` before the page runs; the names: `GeolocaleMgr.currentCountryName`, `currentAdm1Name`). Looked at: `countryName=` and `country=` on every page, `name=` on `country.do`; `adm1Name=`, and `name=` on `adm1.do`, with the country given beside it. So `country.do?name=USA`, `taxonomicPage.do?rank=genus&countryName=USA`, `advancedSearch.do?...country=USA` and `adm1.do?name=MA&country=USA` open the pages of United States and Massachusetts. Before, they opened the empty page of the not-valid place ("This location is Invalid"), an empty list, and "not found". Answered as before: a valid name, an unknown name, an old name without a valid name; the search parameter `adm1=` (a specimen keeps the state as its file wrote it); posts; Edit Geolocale, the Geolocale Manager and the adm1 tool (they work on the old-name rows themselves, by id or name). The page of a not-valid place with a valid name can no longer be opened by its name; `editGeolocale.do?id=` shows the row. The API does the same for `country=` (docs/flows/api.md). Tests: `OldPlaceNamesTest`, `tests/e2e/test_old_place_names.py`.

Use species.", "Country not found for countryName:<name>"; maps: "Enter parameters for a map", "No map found for target:...".
