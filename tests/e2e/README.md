# AntWeb end-to-end tests

These tests drive a running AntWeb over HTTP, like a visitor or curator. They don't depend on Struts internals, so they stay valid while the web layer is upgraded (plan: `antweb-struts-plan.md`).

Default target: https://staging.antweb.org. They never change data, with one exception below; the write-action checks call data-changing URLs anonymously, with no parameters, and are refused on production.

Exception: `test_page_editor.py`, `test_field_history.py` and the write tests in `test_browser_editor.py` (page-text editor safety, history and restore) save and clears text on staging only, in two agreed test records: the taxon page Polyrhachis amana, field Comments, and specimen CASENT0922067, field Notes. It runs a write test only if that field is empty at the start, and leaves it empty. It skips itself on any host other than staging.antweb.org or a local server, and where the editor safety code is not deployed yet.

## Files
- `survey.py` requests every Struts action anonymously, crawls public pages for real example URLs, and calls the API. It writes a report (GitHub job summary, `out/survey.json`) and a candidate baseline (`out/expectations.json`).
- `expectations.json` is the recorded baseline: what each action and crawled page returned.
- `test_actions.py` checks every action and recorded page against the baseline, checks that every action in `struts-config.xml` has an expectation, and checks that data-changing actions ask for a login.
- `test_page_editor.py` checks the page-text editor's safety rules (refused saves keep the text, no empty or stale saves, clear, CSRF), as a curator, on staging only.
- `test_field_history.py` checks page-text History and Restore (`fieldHistory.do`): login required, no [History] link for visitors, versions listed, a restore works through the normal save and records history, a stale or anonymous restore is refused, a clear entry cannot be restored, a cleared field's old text can; taxon and specimen. Staging only, test fields only.
- `test_editor_roundtrip.py` tests the TinyMCE page editor locally, with no AntWeb server: it serves this repository's `web/` folder with a stand-in edit form and runs the real `HtmlSanitizer` (compiled with `editor/EditorRules.java`; needs a JDK). It checks the shared setup sets `license_key: 'gpl'` (TinyMCE 8 is read only without it, which is also tested), that sample stored HTML (tables, font/center/div, images, a video iframe, `&nbsp;`, escaped `&lt;`, loose text with `<br>`, Word styles) is sent back unchanged when saved without edits and shows the same page in the editor, that edits add no `<p>` to text stored without one, the empty-save block, Clear, draft restore and phone width.
- `test_browser_editor.py` opens the real edit form on staging as the test curator (Playwright): the Clear button asks first; TinyMCE starts editable with no JavaScript errors; the stored text is shown; an empty save is refused; an edit is saved and shown on the page; a save from a second tab is refused as a conflict with the text kept; a draft is offered after leaving the page; the form fits a phone (390 px); the CKEditor fallback (`pageEditor=ckeditor`) still loads. History: the [History] link opens the versions, Restore asks for confirmation and restores, with no JavaScript errors. It writes only the agreed test field, only when empty, and leaves it empty.
- `test_overview_editor.py` checks the page text of project and geolocale pages (the same editor and safety rules as taxon pages): the settings forms (editProject.do, editGeolocale.do) need a login and link to the page editor instead of the old page-text boxes; anonymous saves are refused with the text kept; as the test curator, not-ready and stale saves are refused and change nothing. It never writes (there is no agreed test project or country field).
- `test_browser_overview_editor.py` opens the Contents editor of a project page and a country page as the test curator (Playwright): TinyMCE 8 starts editable, the form becomes ready, no JavaScript errors. Nothing is typed or saved.
- `test_geolocale_edit.py` checks that editGeolocale.do changes data only by POST with the form token: anonymous requests get the log-in page; as the test curator, a GET with save parameters and a POST without the token are refused and the stored values are unchanged. The curator checks run only where the POST form is deployed; nothing is changed.
- Manual testing of drafts and two-tab conflicts: while the editor has unsaved text the browser asks "Leave site?" when you go to another page. Click **Leave**: the text is kept in the browser as a draft, and reopening the field offers "Restore my unsaved text". The tests accept that dialog the same way.
- `test_request_handling.py` checks request handling. Anonymous, on any host (read-only GETs): quote characters in taxonName on curation.do and curator.do give a normal page; error pages show no exception text; the server-busy report is not public. As the test curator, staging only, changing nothing: defaultSpecimen.do redirects within the site and changes data only by POST with the form token, for known names; the bioregion map refresh is a POST for administrators; the map managers refuse unknown names; History Restore forms post to fieldHistory.do itself, for page-text pages only; the form token is read from the body of a normal POST. Probes that would change data on a server without this code are skipped there.
- `test_home_page_links.py` checks the links on the home page: AntWeb links (150 spread over the page by default, `ANTWEB_HOME_LINK_SAMPLE=0` for all) must open a real page; outside links fail only if the page is gone (404/410) or the site does not answer.
- `test_upload_report_links.py` opens the newest specimen upload report and the newest Worldants upload report as the test curator and checks their links (up to 80 per report, spread over the report) answer 200 and are not "not in the AntWeb database" or not-found pages. Read-only. `test_image_upload.py::test_report_specimen_links_open_specimen_pages` does the same for the image upload report's specimen links. `test_curate_page_links` checks every link on curate.do the same way, except links that start jobs or change data (util.do, utilData.do, schedule.do, upload.do and the actions in `policy.py`).
- `test_image_upload.py` checks the Image Uploader's one-file-per-request endpoint (`imageUploadBatch.do`, steps start / add / finish): anonymous POSTs and GETs are refused; as the test curator, POSTs without the form token or with a wrong one are refused; file naming rules, file type and specimen checks; one file per request; an unknown upload or one started by another login cannot be added to or finished; a form post to `imageUploader.do` (the old upload without JavaScript, removed 2026-10) only gets "The Image Uploader needs JavaScript" and saves nothing. It uses `dryRun=1`, which checks everything and saves nothing. Staging only. `test_real_upload_round_trip` really uploads three small JPEGs (shot numbers 91 to 93) and is off unless `ANTWEB_IMAGE_UPLOAD_WRITE_TEST=1` and `ANTWEB_IMAGE_UPLOAD_TEST_SPECIMEN` are set; confirm first that staging's `/mnt/antweb` is not the production images bucket.
- `test_browser_image_upload.py` opens `imageUploader.do?dryRun=1` as the test curator (Playwright), selects four small JPEGs and one badly named file, and checks each good file is sent in its own request and marked done, the bad one is not sent and shows why, the page says "Upload finished", and there are no JavaScript errors. Saves nothing.
- `test_previous_determinations.py` checks a specimen page still renders with its data (the page loses it if the `previous_determinations` column is missing) and, for three CAS specimens with previous determinations in TaxonWorks, that "Previous determination:" shows one entry per line, escaped. Skips those three until a TaxonWorks upload with this feature has run on the server. Read only.
- `test_jsp_allow_list.py` checks Caddy's direct-JSP allow-list (the `@jsp_not_allowed` matcher in `docker/caddy/Caddyfile.common`, read by `caddy_lists.py`): JSPs not on the list get Caddy's plain-text "Not found" 404; every listed JSP gets some other answer from Tomcat; the production and staging lists are the same (`python3 tests/e2e/caddy_lists.py` also runs in the PR checks). Read-only.
- `test_login_needed.py` checks that field guides, compare results and map of results (fieldGuide.do and friends) give anonymous visitors the log-in page with an explanation, and that the return target is the requested page (a same-site relative path; another site's Referer is ignored). Read-only.
- `test_documentation_links.py` checks every same-site link on the Participate page (documentation.do) answers 200 and is not a not-found page. Anonymous, read-only.
- `test_header_version.py` checks the page header shows the version and, when the server has `etc/git-commit` (written by deploy.sh), the deployed commit as a 7-character hash linked to the full commit on GitHub. Read-only.
- `test_api.py` checks API v3.1 returns JSON. Note: `api.py` returns an empty response unless the request has `up=1`.
- `policy.py` lists actions never called automatically, data-changing actions, and crawl seeds.
- `test_browser.py` opens pages in a real browser (Playwright, headless Chromium), because the other tests never run a page's JavaScript. It checks: the header Taxa and Places boxes show suggestions ("campon" gives Camponotus, "madag" gives Madagascar); no uncaught JavaScript errors on key pages (home, genus, species, specimen, images, bigMap, advanced search, login, Madagascar); every local script and stylesheet on those pages returns 200 and has the `?v=<hash>` version (so browsers never keep an old copy, see `src/org/calacademy/antweb/util/Asset.java`); and no JavaScript errors at phone width (390x844). It only opens pages and types into the search boxes. Skipped if Playwright is not installed.

## Running
- GitHub: Actions > End-to-end tests > Run workflow (mode `test`, `survey` or `record`). It also runs on every pull request and daily at 13:17 Pacific.
- Locally: `pip install -r tests/e2e/requirements.txt; python -m playwright install chromium; ANTWEB_URL=https://staging.antweb.org pytest tests/e2e`
- Browser tests only: `pytest tests/e2e/test_browser.py`. In GitHub the browser goes through the same SSH tunnel as the other tests (`ANTWEB_BROWSER_HOST_RULES` maps staging.antweb.org to the tunnel; `ANTWEB_BROWSER_IGNORE_HTTPS_ERRORS=1` accepts staging's origin certificate, never honoured for production).

## When a test fails
Either AntWeb broke (fix it), or the change was intended: re-record with mode `record`, and review the diff of `expectations.json` in the pull request.
